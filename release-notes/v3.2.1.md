## Highlights

XEXAMAI 3.2.1 delivers the complete 3.2 feature set: automatic interview assistance, realtime speech translation, and a native screenshot workflow, with a strong focus on keeping interrupted requests, transcripts, and image attachments consistent.

### Automatic answers

- Added Auto Mode: XEXAMAI can detect the end of a spoken question and submit it automatically after a calibrated silence instead of requiring a manual Send action.
- Auto Mode works with buffered audio, realtime transcription, and realtime translation while preserving the correct recording and provider lifecycle.
- If speech resumes, an in-flight automatic request is cancelled and reconciled. A continued question is rebuilt, while a genuinely new turn does not inherit stale transcript text.
- Useful interrupted drafts may remain visible, but superseded or incomplete turns are excluded from future model context so they cannot distort later answers.
- Screenshot attachments use one-shot ownership: interrupted requests resend the actual image bytes when needed, successful answers consume them once, and images are not duplicated into persistent chat history.

### Realtime translation

- Added OpenAI Realtime Translate as a transcription option with a configurable output language and automatic recognition of multilingual and code-switched speech.
- The translated transcript is written directly into the question composer; a compact switch lets you inspect the original or translated text without changing which text is submitted.
- Hardened realtime session setup, acknowledgement, commit/finalization, reconnect, cancellation, and shutdown behavior so late provider events cannot overwrite a newer session or clear speech received during a request.
- Preserved user edits and newly received transcript fragments across asynchronous dispatch and manual or automatic submission.

### Native screenshots

- Replaced the browser screen-sharing picker with a native Windows screenshot flow for the main capture action.
- Added a dimmed selection overlay for drawing a capture rectangle, plus a one-click full-screen capture action and safe cancellation.
- Added monitor/DPI-aware coordinate handling, stale-session rejection, deterministic native resource cleanup, and production bundling for the overlay entry point.
- The capture lifecycle respects XEXAMAI's screen-capture privacy behavior and prevents late screenshots from being attached after sign-out, update installation, shutdown, or a newer capture session.

### Interface and settings

- Matched the Screenshot and Auto Mode controls to the same 32 × 32 px hit area with consistent 20 × 20 px icons.
- Saved OpenAI and Google credentials now appear as a write-only mask instead of an apparently empty field. Short placeholders fit narrow windows, and the mask can never be submitted as a replacement key.
- The last selected Settings section is remembered when moving between Main, Settings, and Profile during the current application session.
- Refined the question composer and realtime translation control while retaining multiline growth, image thumbnails, and compact actions.

### Reliability and privacy

- Added generation and request guards across provider proxy, transcription, Ollama, OpenAI realtime, renderer bridge, and screenshot operations to suppress stale completions and cancellation races.
- Improved automatic-turn media timing so bursty native audio callbacks do not double-count silence or trigger premature submissions.
- Image pixels remain outside persisted chat history; cancelled multimodal turns are retried with the original attachment only when required.
- Fixed cross-platform compilation of the Windows-gated native screenshot result and verified the release on Linux CI before tagging.
- Expanded regression coverage for automatic endpointing, multimodal attachment ownership, realtime acknowledgement, provider cancellation, native screenshot selection, renderer shutdown, API-key presentation, and Settings navigation.
