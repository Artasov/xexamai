XEXAMAI — настольное приложение на Tauri 2. Оно хранит скользящий аудиобуфер в памяти, распознаёт выбранный фрагмент и отправляет распознанный вопрос выбранной AI-модели. Доступны микрофон, системный звук и смешанный режим; наиболее полно системный звук поддерживается в Windows.

Используйте приложение только там, где разрешены запись и помощь AI. Пользователь сам отвечает за согласие участников, конфиденциальность и соблюдение правил собеседования, экзамена, встречи или используемого сервиса.

## Возможности

- Нативный захват аудио на Rust: микрофон, системный звук и смешанный режим.
- Переключение источника во время записи, настраиваемая длительность буфера и глобальные горячие клавиши.
- OpenAI, Google Gemini, Google Live, Winky, Ollama и локальный `fast-fast-whisper`.
- Потоковые ответы и realtime-транскрипция Google прямо в поле вопроса.
- Локальная история с поиском, фильтрами, закреплением, переименованием, повтором, экспортом, удалением и сроком хранения.
- Анализ скриншота через OpenAI или Google только по явному действию пользователя.
- Вход через OAuth или email/пароль для backend XEXAMAI и функций Winky.
- Подписанные загрузки обновлений внутри приложения с отдельным подтверждением установки.
- Always-on-top, прозрачность, масштаб и best-effort скрытие окна от захвата в Windows.

Локальные режимы не расходуют квоту OpenAI или Google, но требуют локального ПО и ресурсов компьютера. Облачные режимы подчиняются условиям, квотам, оплате и правилам обработки данных соответствующего провайдера. Для Winky могут требоваться аккаунт XEXAMAI и кредиты; обработка скриншотов сейчас также требует серверной проверки feature entitlement, даже если используется собственный provider key пользователя.

## Быстрый старт

1. Установите сборку из [GitHub Releases](https://github.com/Artasov/xexamai/releases/latest) и откройте XEXAMAI.
2. Авторизуйтесь и выберите режим AI и транскрипции в **Settings**.
3. Для BYOK-режима OpenAI или Google добавьте соответствующий API-ключ. Для локального режима запустите Ollama и/или локальный speech-сервис.
4. Выберите **Microphone**, **System audio** или **Mic + System**, а при необходимости — конкретный микрофон.
5. Запустите запись. XEXAMAI хранит в скользящем буфере только настроенный последний отрезок. Если выбрана модель транскрипции Google Live, одновременно начинается непрерывная отправка аудио в Google — до остановки записи или смены режима.
6. Отправьте нужную длительность, напечатайте вопрос, включите потоковый режим или явно сделайте скриншот.

До важной сессии проверьте звук и доступ к провайдеру. Первый локальный запрос может выполняться дольше из-за скачивания или загрузки модели в RAM/VRAM.

## Куда уходят данные

Слово «локальный» описывает место выполнения инференса, а не гарантирует полный офлайн-режим всего приложения. При запуске приложение автоматически восстанавливает существующую сессию и профиль, обновляет профиль/entitlement после возврата focus или visibility и примерно каждые пять минут в активном состоянии, а также проверяет подписанный канал обновлений при старте и периодически. Вход, feedback и включённые provider-режимы выполняют описанные ниже запросы.

| Режим или действие | Какие данные отправляются | Куда |
| --- | --- | --- |
| Локальная речь (`fast-fast-whisper`) | Выбранный фрагмент аудио | Локальный сервис `127.0.0.1:8868` |
| Локальная LLM (Ollama) | Промпт и выбранный контекст диалога | Локальный сервис `127.0.0.1:11434` |
| OpenAI | Выбранное аудио, промпт/контекст или скриншот — в зависимости от действия | `api.openai.com` |
| Обычный режим Google | Выбранное аудио, промпт/контекст или скриншот — в зависимости от действия | `generativelanguage.googleapis.com` |
| Google Live | При старте записи с выбранной Live-моделью аудио непрерывно отправляется через прямой WebSocket; renderer использует одноразовый временный токен | Google Live API |
| Winky | Запросы аккаунта/профиля, промпт/контекст или загруженный фрагмент аудио | Выбранный backend `xlartas.com` или `xlartas.ru` |
| Обратная связь | Тема, текст, контакт, выбранные изображения и опциональная диагностика | Выбранный backend XEXAMAI |

Для аккаунтов с entitlement `history` история диалогов хранится локально в профиле webview отдельно для каждого backend и аккаунта. Без него текущий диалог остаётся только в памяти, а ранее сохранённые данные не загружаются и не удаляются. Выход из аккаунта изолирует его историю, но не удаляет её. Срок по умолчанию — 90 дней; закреплённые диалоги сохраняются, пока их не открепят или не удалят. Пиксели скриншота в историю не записываются, но сохраняются отметка о скриншоте, промпт и ответ.

XEXAMAI ведёт локальные диагностические логи. В них могут попадать короткие фрагменты промптов, транскрипций и ответов. Поля, похожие на credentials, удаляются по best-effort правилам, однако лог всё равно следует считать потенциально чувствительным. Автоматической отправки логов нет; очищенный фрагмент добавляется к конкретному обращению только при включённом чекбоксе диагностики.

Ручная настройка `save_recorder_files` по умолчанию выключена. Если её включить, отправляемые аудиофрагменты дополнительно сохраняются как raw debug-файлы в `transcription_debug` внутри local app data без автоматического срока хранения. Удаляйте их вручную, когда они больше не нужны.

Полная матрица по режимам, хранение credentials, особенности удаления и ограничения платформ описаны в [политике безопасности и конфиденциальности](SECURITY.md).

## Локальный AI

### Ollama

1. Установите [Ollama](https://ollama.com/).
2. Скачайте модель, например:

   ```shell
   ollama pull qwen3:4b
   ```

3. Запустите Ollama, если он ещё не запущен:

   ```shell
   ollama serve
   ```

4. В XEXAMAI выберите хост LLM **Local**, установленную модель и выполните встроенную проверку доступности.

XEXAMAI принимает только loopback endpoint Ollama. Кэш моделей и собственные логи находятся под управлением Ollama.

### fast-fast-whisper

В локальном режиме транскрипции экран Settings умеет установить, запустить, остановить, перезапустить и проверить интеграцию с [fast-fast-whisper](https://github.com/Artasov/fast-fast-whisper). Репозиторий также можно запустить вручную на порту `8868`.

У helper-сервиса есть собственное Python-окружение, скачанные модели, кэш и логи. Его стандартные стартовые скрипты могут слушать все сетевые интерфейсы; на недоверенной сети ограничьте доступ firewall или измените bind-адрес helper. Сам XEXAMAI обращается к `127.0.0.1` и проверяет идентичность сервиса перед тем, как считать endpoint готовым.

GPU-ускорение зависит от helper, модели, драйвера, совместимости CUDA/cuDNN и объёма VRAM. Следуйте актуальной инструкции в репозитории helper вместо фиксированной версии CUDA из README.

## Ограничения платформ

- **Windows:** для системного звука и смешанного режима используется нативный WASAPI loopback. Это основной протестированный путь.
- **macOS:** микрофон работает через системный audio API. Для системного/смешанного режима нужен виртуальный вход, например BlackHole, Loopback или Soundflower, и необходимые разрешения ОС.
- **Linux:** для системного/смешанного режима нужен monitor source PulseAudio или PipeWire. Поведение desktop portal, compositor, tray и горячих клавиш может отличаться.
- **Скриншот:** при каждом захвате показывается системный/webview picker. Выбранный кадр уменьшается перед обработкой.
- **Скрытие от захвата:** в Windows используется `SetWindowDisplayAffinity` как best-effort механизм. Это не гарантия невидимости: результат зависит от версии Windows, программы записи, Remote Desktop и способа захвата. Аналогичное исключение не реализовано для macOS и Linux.

## Разработка

### Требования

- Node.js 24 и npm
- Rust 1.97 и Cargo
- [Зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/) для текущей платформы

### Запуск

```shell
git clone https://github.com/Artasov/xexamai.git
cd xexamai
npm ci
npm run dev
```

### Основные команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить Tauri-приложение в dev-режиме |
| `npm run dev:renderer` | Запустить только Vite renderer |
| `npm run typecheck` | Проверить TypeScript |
| `npm test` | Запустить тесты renderer |
| `npm run build:renderer` | Собрать только renderer |
| `npm run build` | Собрать и упаковать Tauri-приложение для текущей host-платформы |
| `npm run bindings:generate` | Пересоздать Rust-to-TypeScript IPC bindings |
| `npm run bindings:check` | Проверить сгенерированную карту IPC-команд |

Пакеты создаются в `src-tauri/target/release/bundle/`. Релизные артефакты Windows, macOS и Linux собираются на соответствующих runner; локальный `npm run build` собирает пакет только для текущей host-платформы и toolchain.

### Структура проекта

```text
src/
├── renderer/       # React renderer и интерфейс приложения
└── shared/         # Общие и сгенерированные TypeScript-контракты
src-tauri/
├── src/            # Rust host, аудио, auth, updater и provider proxy
├── capabilities/   # Разрешения команд Tauri
└── tauri.conf.json # Конфигурация desktop-приложения и пакетов
scripts/            # Release-, version- и update-manifest tooling
```
